# Haier Evo integration
[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/custom-components/hacs) [![stability-beta](https://img.shields.io/badge/stability-beta-33bbff.svg)](https://github.com/mkenney/software-guides/blob/master/STABILITY-BADGES.md#beta)

Неофициальная интеграция для работы [Haier Evo](https://haieronline.ru/evo-iot/) (RU, KZ, BY).

Бета-версия: может работать некорректно.

## Поддерживаемые устройства
Ниже приведен список типов устройств, работа с которыми была **проверена пользователями**:

- Кондиционеры
- Холодильники

В действительности интеграция должна поддерживать больше устройств. 
Если интеграция некорректно работает с вашим устройством или поддерживает не все функции - сообщите в [Issues](https://github.com/and7ey/haier_evo/issues) об этом. 

## Совместимость
Haier предлагает разные мобильные приложения для разных рынков и стран. Некоторые устройства совместимы с более чем одним приложением. Эта интеграция поддерживает только устройства, которыми можно управлять через приложение [Evo](https://haieronline.ru/evo-iot/). Загрузите приложение Evo и проверьте совместимость с вашим устройством.

## Установка

### 1. Установка HACS (если не установлен)
Для работы интеграции требуется наличие HACS.
Инструкция для установки https://www.hacs.xyz/docs/use/download/download/

### 2. Добавление репозитория Haier Evo

Так как интеграция является кастомной, её необходимо добавить в HACS как пользовательский репозиторий:

1. Откройте **HACS** в боковой панели Home Assistant.
2. Нажмите на три точки (⋮) в верхнем правом углу и выберите **Custom repositories** (Пользовательские репозитории).
3. В поле **Repository** вставьте ссылку: `https://github.com/and7ey/haier_evo`
4. В поле **Category** выберите **Integration** (Интеграция).
5. Нажмите **Add** (Добавить).
6. Теперь найдите **Haier Evo** в поиске HACS и нажмите **Download** (Загрузить).

### 3. Настройка

1. Перезапустите Home Assistant.
2. Перейдите в **Настройки** > **Устройства и службы** > **Добавить интеграцию**.
3. Найдите в списке **Haier Evo** и введите данные вашего аккаунта от приложения Evo.

## Окно стиральной и сушильной машины

У каждой поддерживаемой машины появляется основная сущность `haier_evo` с именем и состоянием устройства в разделе «Управление». Её можно добавить на панель обычным способом. Нажатие открывает окно с программами, состоянием и двумя объединёнными элементами управления. Выбор следующей программы находится в разделе «Настройки». Команды доступны также через действие `haier_evo.execute_action`; отдельные кнопки для каждой команды не создаются. Иконки программ подбираются по их названиям, а неизвестные названия получают общую иконку одежды.

Окно открывается обработчиком события интерфейса Home Assistant только для этих сущностей. Сущность использует собственный домен интеграции, а не штатный тип стиральной машины. Окно использует нестандартный механизм: после обновлений интерфейса его совместимость требуется проверять. Если обработчик не загрузился, Home Assistant покажет обычное окно сущности.

Выбор программы не запускает машину. Запуск и отмена требуют подтверждения. При известном состоянии доступны подходящие ему команды. Если состояние цикла не передано, пользователь выбирает конкретное действие вручную; связь и удалённый доступ обязательны. Неизвестный код этапа показывается в диагностике, а не подменяется догадкой. Анимация учитывает настройку уменьшения движения. Выполнение команд и получение события завершения необходимо проверить на конкретном устройстве.

## Проверка изменений

```sh
python3 -m unittest discover -s tests -v
```

Тесты обнаружения устройств и запуска интеграции используют синтетические ответы
облака и подменяют границы Home Assistant. Выполняются реальные функции из
исходников интеграции; установка Home Assistant, учётные данные и доступ к
устройствам не требуются.
Ошибки машины отображаются отдельным датчиком в разделе «Диагностика»: код, описание и рекомендация берутся из данных Haier. Пустой подтверждённый список означает отсутствие активных ошибок; потеря данных не считается исправностью. События `ProgramWasherBaseEvent`, `ProgramDryerBaseEvent` и `alarms` используются для быстрых обновлений состояния.

Для уведомлений интеграция публикует событие `haier_evo_laundry_event` с полями `type` (`program_finished`, `error`, `error_cleared`), `entity_id`, `name`, `model`, `kind`, `program` и `errors`. Первичная загрузка состояния не создаёт уведомления. Повтор одной ошибки или одного события завершения подавляется. Наличие ошибок в событии завершения не означает успешного выполнения программы. Получателей и канал уведомлений выбирают автоматизации владельца.

### Восстановление после отключения

При возвращении устройства online и после восстановления WebSocket интеграция запрашивает полный снимок состояния. Резервная сверка выполняется раз в минуту для недоступной или работающей машины и раз в пять минут для доступной машины в ожидании. Все её сущности используют один координатор, запросы устройств сериализуются с общим минимальным интервалом 15 секунд. События не могут бесконечно откладывать контрольный опрос.

При ошибках пауза растёт от 60 до 900 секунд; `Retry-After` сервера учитывается, а лимит 429 приостанавливает запросы остальных машин этого аккаунта. Восстановление связи не создаёт push-уведомлений. Старый HTTP-ответ не перезаписывает более новые события устройства; неполный ответ не разрешает управление. WebSocket проверяет ответы на ping с ограниченным ожиданием.
